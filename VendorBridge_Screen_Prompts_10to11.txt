This design system is identical to the one used in Screens 1–9; it is reprinted here for self-contained reference.

Spacing & Layout
	•	4px baseline grid — all spacing is a multiple of 4px
	•	Sidebar width: 260px (fixed); Main content: fluid 12-column grid, max-width 1440px
	•	Page margin: 32px; Gutter between columns: 24px
	•	Compact density (table rows, list items): 8px padding; Comfortable density (cards, forms): 16px padding

Elevation & Depth
	•	Level 0 — App Canvas: Surface Muted (#F4F7FF), no border
	•	Level 1 — Cards & Tables: Pure White (#FFFFFF) with 1px Border Subtle (#E2E8F0), no shadow
	•	Level 2 — Dropdowns & Tooltips: White + shadow: 0px 4px 6px -1px rgba(0,0,0,0.05)
	•	Level 3 — Modals: White + shadow: 0px 20px 25px -5px rgba(0,0,0,0.1)

Global Component Rules
	•	Primary Button: Filled #0154CC, white text, 4px radius — for primary submit / confirm actions
	•	Secondary Button: 1px border (#E2E8F0), Data Ink text, white background — for cancel / secondary actions
	•	Success Button: Filled #10B981, white text — exclusively for Approve / + Add / Export / Finalize
	•	Danger Button: Filled #BA1A1A, white text — exclusively for Reject / Delete / Revoke
	•	Input Fields: White bg, 1px Border Subtle (#E2E8F0), 2px radius, primary-color focus ring, left Material Symbol icon
	•	Side Nav Active: 4px solid Primary left accent bar + Surface Muted background fill + Primary text + filled icon (FILL=1)
	•	Table Headers: label-caps font, Surface Muted (#F4F7FF) background, 1px bottom border; NO zebra striping — hover (#F8FAFC) only
	•	Icons: Material Symbols Outlined, 2px stroke weight, 20–24px size throughout

Screen 10: Reports & Analytics Screen
Purpose: Provide procurement leadership, finance controllers, and admin users with a comprehensive, data-driven intelligence hub. This screen converts raw procurement transaction data into actionable visual insights — vendor performance rankings, monthly spending curves, RFQ-to-PO conversion funnels, budget utilization gauges, and exportable compliance reports. The screen is read-heavy and chart-dense, demanding careful layout discipline to keep the data accessible rather than overwhelming. All charts follow a Corporate Blue → Lavender → Amber palette to maintain brand consistency while encoding distinct data dimensions.

▸  Left Cluster
	•	Page title: "Reports & Analytics" — headline-md (Hanken Grotesk, 24px, weight 600, On-Surface #1C1B1B)

Active selection highlighted with Primary (#0154CC) text and check_circle icon.

Screen 11: User Management & Admin Panel Screen
Purpose: Provide system administrators with complete oversight and control of all user accounts within the VendorBridge ERP. This screen enables admins to register new users, assign and modify role-based access permissions (Procurement Officer / Vendor / Manager / Admin), suspend or deactivate accounts, audit login activity, and manage organizational hierarchy. The screen is the security and access-control nerve center of the platform, so the design must communicate authority and precision — no ambiguity in permission states, no hidden actions.
Active Navigation State: "User Management" nav item is active in sidebar — manage_accounts icon (filled FILL=1, Primary blue) + "User Management" label in Primary, 4px solid Primary left accent bar, Surface Muted background fill. This is the only screen that activates this specific nav item.

11.5 — Row Context Menu (triggered by "⋯" overflow icon)
A Level 2 dropdown (white bg, 4px radius, 200px width, shadow: 0px 4px 6px -1px rgba(0,0,0,0.05), 8px vertical padding). Positioned below and right-aligned to the trigger icon. Menu items (each 36px height, 16px horizontal padding, body-md font, flex row with 12px gap between icon and label):
	•	"View Profile" — person icon (20px, Outline) + "View Profile" (Data Ink); hover: Surface Muted bg
	•	"Edit User" — edit icon (20px, On-Surface Variant) + "Edit User" (Data Ink); hover: Surface Muted bg
	•	"Change Role" — manage_accounts icon (20px, On-Surface Variant) + "Change Role" (Data Ink); hover: Surface Muted bg. Opens a secondary panel/modal
	•	"Reset Password" — lock_reset icon (20px, Outline) + "Reset Password" (Data Ink); sends password reset email
	•	1px separator (Border Subtle) between the standard actions and destructive actions below:
	•	"Suspend Account" — block icon (20px, Error) + "Suspend Account" (Error #BA1A1A); hover: Error-tinted bg (#FFDAD6). Only shown if user is currently Active
	•	"Reactivate Account" — check_circle icon (20px, Success) + "Reactivate Account" (Success #10B981). Only shown if user is currently Suspended
	•	"Remove User" — delete_forever icon (20px, Error) + "Remove User" (Error #BA1A1A); hover: Error-tinted bg. Triggers a confirmation dialog before action
	•	The menu closes on any outside click (click-away listener). Menu position adjusts if near the viewport bottom edge to open upward instead.

	•	Right side action buttons (all label-bold, 4px radius, 10px v / 14px h padding):
	•	"Change Roles" — secondary button (1px border, Data Ink) with manage_accounts icon (18px)
	•	"Send Password Reset" — secondary button with lock_reset icon (18px)
	•	"Suspend Selected" — Danger button (Error fill #BA1A1A, white text) with block icon (18px) — only appears if all selected users are Active
	•	"Reactivate Selected" — Success button (#10B981 fill, white text) with check_circle icon (18px) — only appears if all selected users are Suspended

11.10 — Confirmation Dialog (for destructive actions)
When actions like "Remove User" or "Suspend Account" are triggered, a Level 3 centered confirmation dialog appears (NOT a toast). Spec:
	•	Dialog card: white bg, 480px max-width, 8px radius, shadow: 0px 20px 25px -5px rgba(0,0,0,0.1), 24px padding; dimmed overlay rgba(0,0,0,0.5)
	•	Top: a 48×48px circle — Error fill (#BA1A1A) with warning icon (warning, 28px, white) — centered above title text
	•	"Suspend Account?" or "Remove User?" — headline-sm, weight 600, On-Surface, centered
	•	Body: body-md, On-Surface Variant, centered — "Are you sure you want to suspend Jane Doe's account? They will immediately lose access to all VendorBridge modules." (text is context-aware)
	•	Footer: "Cancel" secondary button (1px border, Data Ink) + confirm action button ("Suspend Account" / "Remove User") in Danger fill (#BA1A1A, white text, label-bold) — right-aligned, 8px gap
	•	Secondary safety: "Type the user's name to confirm" text input appears for irreversible actions (Remove User only). Confirm button stays disabled (50% opacity) until the input matches the user's name exactly (case-insensitive)

11.11 — Toast Notification System
After completing actions (invite sent, user edited, account suspended, etc.) the system shows a toast notification — a non-blocking status message that appears in the top-right corner of the viewport:
	•	Position: fixed top-right, 24px from top and right edges of viewport; z-index above all content except modals
	•	Width: 320px; padding: 16px; 8px radius; white bg; Level 2 shadow (0px 4px 6px -1px rgba(0,0,0,0.05)); 1px Border Subtle
	•	Left-side vertical accent strip (4px wide, full height, 0px left radius): Success Accent for success toasts, Error for failure, Amber for warnings
	•	Content row: icon (20px) + text block (flex, align-items: flex-start):
	•	Success: check_circle icon (Success Accent) + "Invitation sent successfully." (body-md, weight 600, On-Surface) + "Jane Doe will receive an email at jane.doe@company.com." (body-sm, Outline)
	•	Error: error icon (#BA1A1A) + error headline + description
	•	Warning: warning icon (amber) + warning headline + description
	•	✕ dismiss button (cancel icon, 16px, Outline) — top-right corner of toast
	•	Auto-dismiss after 5 seconds with a thin progress bar (4px height, Primary blue) depleting from full-width to 0 along the bottom of the toast card
